# script.js のファイル分割 設計

日付: 2026-10-08 / 状態: 承認待ち（設計は会話で承認済み、本書は仕様書レビュー用）

## 目的

`script.js`（約2,700行、全体が1つの IIFE）を、章ごとの複数ファイルに分ける。
Codex と Claude Code が同じリポジトリを触るので、「触る範囲が小さく分かれている」状態にして、読み違いや巻き込み事故を減らす。

**成功基準**
1. 見た目・動作・保存データが分割前と完全に同じ
2. 既存テスト（全件）が、テスト本体を変えずに（読み込み元の1行を除く）合格する
3. オフラインでも動く（Service Worker が新ファイルを全部キャッシュする）
4. Codex が構成のルールを破ったとき（`<script>` と `ASSETS` の食い違いなど）、テストが落ちて気づける

## 方針

- **中身は書き換えない。移動だけ。** 関数の中身・名前・順序の変更、仕様変更、リファクタはしない
- ES モジュール化・ビルド導入はしない
- IIFE を外し、ファイルごとの普通の `<script>`（クラシックスクリプト）にする。トップレベルの `let` / `const` / `function` は全ファイルで共有される
- 読み込み順は**元のコードの並び順**と同じにする（切り出し系テストの「目印」の前後関係が保たれる）

## ファイル構成（読み込み順）

| # | ファイル | 元の範囲（現在の行） | 内容 |
|---|---|---|---|
| 1 | `app-core.js` | 1〜323 | 定数、アイコン、`state`、`ui`、保存、トースト、ストリーク、レベル |
| 2 | `app-shell.js` | 324〜557 | `render` 本体、タブ、モーダル |
| 3 | `view-home.js` | 558〜1229 | ホーム、バランス、統計カード |
| 4 | `view-calendar.js` | 1230〜1308 | カレンダー |
| 5 | `view-record.js` | 1309〜1477 | タイマー、記録フォーム |
| 6 | `view-settings.js` | 1478〜1687 | 設定 |
| 7 | `events.js` | 1688〜2634 | クリック・入力、インポート／エクスポート |
| 8 | `sea-backdrop.js` | 2635〜2713 | Service Worker 登録、Deep Sea の背景・動画 |
| 9 | `app-init.js` | 2714〜末尾 | 起動処理 |

- `backup.js` / `range-total.js` / `stats.js` は今までどおり先に読み込む（`script.js` の前）
- 元の `script.js` は削除する
- 切れ目は、元の区切りコメント（`// ---------- ... ----------`）の行を各ファイルの先頭にする。**関数の途中では切らない。** 行番号は目安で、実装時に区切りコメントで確定する
- 先頭の IIFE 開始（`(function(){`）と、末尾の閉じ（`})();`）は取り除く

## テストの扱い

- `tests/helpers/source.js` を新設し、上の9ファイルを**表の順に連結**した文字列を返す
- `script.js` を直接読んでいる11本のテストは、読み込む1行を `require('./helpers/source.js')` に差し替える（それ以外は変えない）
- 連結の順序は `index.html` の `<script>` の順と同じになるように、ヘルパーが `index.html` から読み込み順を取得する（二重管理を避ける）

## 構成を守るためのテスト（新規 `tests/structure.test.js`）

1. `index.html` の `<script src>` のうち、ローカルのファイルが**すべて実在する**
2. `index.html` のローカルの `<script src>`、`<link rel="stylesheet">` が、`sw.js` の `ASSETS` に**すべて含まれている**（食い違いがあれば失敗）
3. `ASSETS` に載っている `.js` / `.css` が**すべて実在する**
4. 分割した `app-*.js` / `view-*.js` / `events.js` / `sea-backdrop.js` は、`index.html` で**表の順**に並んでいる
5. 分割後のファイル内に、トップレベルで**同じ名前の関数・`let`・`const` が重複して定義されていない**（後から読み込まれたほうが上書きして事故になるため）

## 検証（実装時）

分割**前**に基準を取り、分割**後**に比較する。

1. 全テスト合格（分割前後とも）
2. 実ブラウザ（Playwright、375px）で、テスト用データを入れた状態の、ホーム（詳細を開いた状態）・カレンダー・記録・設定の**画面の HTML テキスト（`#canvas` の内容）が、分割前後で一致する**
3. コンソールエラー0件
4. 全トップレベル名が `window` の標準の名前とぶつかっていないことの確認（分割前に IIFE の中だった名前が、グローバルになるため）
5. オフラインで起動できる（Service Worker のキャッシュに全ファイルが入っている）

## 同時に更新するもの

- `index.html`（`<script>` タグ）、`sw.js`（`ASSETS` と `CACHE_NAME` を上げる）
- `AGENTS.md`（構成、読み込み順、新ファイルを足すときの3か所、グローバル共有の注意、テストは `helpers/source.js` 経由）
- `range-total.js` / `stats.js` 先頭のコメント（「`script.js` から呼ぶ」の記述）
- `.claude/settings.local.json` は触らない

## やらないこと（YAGNI）

- `events.js` の細分化（移動後に必要なら別作業）
- 関数の改名・整理・重複除去、スタイルの統一
- ES モジュール化、ビルド導入、TypeScript 化
- 動作・画面の変更

## リスクと対策

| リスク | 対策 |
|---|---|
| 関数の途中で切ってしまう | 区切りコメントの行でのみ切る。分割後に全ファイルの構文チェック（`node --check`） |
| 読み込み順の誤りで起動時にエラー | 元の並び順を保つ。構成テスト4。実ブラウザでコンソールエラー確認 |
| 同名の定義の上書き | 構成テスト5。分割前後の画面一致で検出 |
| `window` の標準名との衝突 | 検証4 |
| オフラインで動かなくなる | 構成テスト2・3、検証5 |
| Codex が新ルールを知らずに崩す | `AGENTS.md` に明記。構成テストが失敗して気づける |
